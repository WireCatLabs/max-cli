# Локальная копия: что хранится и как держать её свежей

Всё, что `max` прочитал, остаётся у вас: из копии можно ответить без сети, искать и выгружать.
Эта страница — о копии: что в ней, как держать её свежей, как дочитать историю и выгрузить её
в файл.

## Что хранится

Прочитанное сохраняется рядом, чтобы было чем ответить без сети:

```sh
max chats list --offline      # только из локальной копии, никуда не подключаться
max messages send 0 "текст" --offline   # отказ: из копии отправить нельзя
max store clear --left        # посмотреть, сколько данных покинутых чатов можно удалить
max store clear --left --allow-dangerous  # удалить их из общей копии
```

Чат, из которого вы вышли или вас удалили, пропадает из `chats list` и `chats show` при следующем
входе. Его сообщения остаются в копии; `max store clear --left --allow-dangerous` стирает их вместе с
чатом (без `--allow-dangerous` команда только говорит, сколько удалит). Если вас вернут в чат, он снова появится в списке.

`chats list|show` и `contacts list|show` хранят прочитанное в общей копии, той же, что у `tg`.
Она заполняется с первого запуска без `--offline` после обновления: прежняя копия `max` в неё не
переносится. Настройки группы (`description`, `access`, `settings`) `chats show` знает только от MAX,
поэтому с `--offline` их в ответе нет.

Обычные команды всё равно спрашивают MAX: ответ на вход и так приносит чаты и контакты, поэтому
отвечать из копии значит сознательно не узнать, что изменилось. `--offline` — это когда сети нет
или когда подключаться не нужно.

MAX получает сохранённую метку контактов, поэтому следующий вход может принести только изменившихся
людей. `max contacts list` отвечает из общей копии, обновлённой этим входом. Чтобы получить весь
список контактов заново, выполните `max contacts sync`.

Старый кэш профиля больше не открывается и в общую копию не переносится. `max doctor` показывает
его путь, если файл остался. Команды удаления всей общей копии нет; `store clear --left` удаляет
только данные покинутых чатов.

### Скачать историю

`max store fetch` скачивает историю одного чата в локальную копию — назад до даты, до числа
сообщений или до начала чата:

```sh
max store fetch Друзья --since-time 2026-01-01
max store fetch Друзья --last 500
max store fetch Друзья --background      # в фоне; `max store jobs show <id>` следит за ним
max store fetch --all                    # все чаты, самые активные первыми: последние 90 дней
```

Она листает назад так же, как веб-версия при прокрутке вверх: по 30 сообщений, от самого старого
загруженного. Между страницами — пауза от `--pause` до вдвое большей (по умолчанию `5s`, то есть
5–10 с: примерно так страницы идут, когда человек листает чат во вкладке). За один запуск — не
больше `--limit` сообщений (по умолчанию 1200, это 40 страниц). Та же команда ещё раз
продолжает с места, где остановилась, и пропускает то, что уже скачано. Без `--since-time` и `--last`
запуски идут до самого начала чата; `--since-time` и `--last` вместе не принимаются. `--since-time` —
время в ISO 8601 или «столько назад» (`30d`). Ctrl-C или `--timeout` останавливают после страницы в работе,
и скачанное остаётся.

Если MAX отвечает, что запросов слишком много, команда останавливается: из ответа MAX `max` не знает, сколько ждать,
поэтому `max` не ждёт и не повторяет запрос. На любой другой ошибке команда тоже останавливается. Скачанное
остаётся, следующий запуск продолжает с того же места ([limits.md](limits.md)). Реакции `store fetch` не читает, прочитанным ничего не отмечает. `--estimate`
для MAX не работает: id сообщений MAX не позволяют сосчитать, сколько не хватает.

Скачанное ложится в общую локальную копию, ту же, что у `tg` (путь показывает `max store info`).
`max store status` показывает по каждому чату, сколько сообщений хранится и какие куски скачаны
целиком. Копия, которую `max` вёл до общей, в неё не переносится — историю скачайте заново.

Фоновые скачивания показывает `max store jobs list`, останавливает — `max store jobs cancel <id>`.

Уход за файлом копии:

- `max store check` — цел ли файл, индексы поиска и место на диске, какие чаты отстали;
- `max store backup <файл>` — копия файла на ходу, существующий файл не перезаписывается;
  `max store restore <файл>` кладёт её на место, а прежний файл оставляет рядом. С `--encrypt` копия
  сжимается и шифруется паролем — см. [Пароль](#пароль);
- `max store reindex` — заново строит индекс поиска, словарь опечаток и основы слов; сообщения не теряются;
- `max store migrate` — переводит файл на схему этой версии `max` и достраивает индексы для старых сообщений.

### Выгрузить в файл

Переписку из локальной копии можно выгрузить в файл — в JSONL (те же объекты, что
`messages list --jsonl`) или в Markdown для чтения:

```sh
max store export Друзья --format markdown --output друзья.md
max store export 111 --format jsonl --since-time 2026-09-01 > чат.jsonl
```

Выгрузка **никуда не подключается** и берёт только то, что уже скачано или прочитано; дочитать
назад — `max store fetch <чат>`. Существующий файл она не перезаписывает. Файл из `--output`
доступен только вам (`0600`): в нём ссылки на фото, которые открываются без входа.

### Выгружать в папку и добавлять только новое

`--to <папка>` пишет чаты в папку: по файлу JSONL на чат и `manifest.json`. Повторный запуск в ту же
папку добавляет только то, что изменилось с прошлого раза: новые сообщения, правки (в том числе старых
сообщений) и удаления. Удалённое сообщение записывается без текста — `{ "id", "chatId", "deleted": true }`.

```sh
max store export Друзья Работа --to ~/max-архив
max store export --kind group --to ~/max-группы
max store export --all --to ~/max-всё
```

Папку с чужими файлами или выгрузку другого аккаунта `max` не трогает. Изменение одних реакций
изменением не считается.

### Пароль

`--encrypt` у `store export` (с `--output` или `--to`) и у `store backup` сжимает файл и шифрует его
паролем. Внешние программы не нужны. Открыть такой файл — `max store decrypt <файл> --output <новый файл>`;
`max store restore` сам спросит пароль зашифрованной копии.

- **Пароль нигде не сохраняется** — ни в настройках, ни в хранилище паролей, ни в журнале. Забыли его — файл
  не открыть.
- Сами вводите пароль в терминале: он не показывается и спрашивается дважды. Агент, которому вы дали
  пароль, передаёт его через stdin, а не в аргументе команды — аргумент виден другим программам:

  ```sh
  printf '%s' 'пароль' | max store backup ~/max.sealed --encrypt
  ```

- В зашифрованную папку пишется один файл на запуск. `manifest.json` в ней без названий чатов, и
  запуск с другим паролем `max` не примет.

## Поиск

`max search messages` находит сохранённые сообщения по словам, отправителю, чату, дате, файлам,
ссылкам и вашим меткам. Поиск слов в одном названном чате по умолчанию спрашивает ещё и сервер MAX;
без чата или с `--backend archive` читает только архив. `--sync-first` сначала ограниченно
скачивает новые сообщения из MAX, не отмечая их прочитанными. Руководство — [поиск сообщений](search.md), там же
сохранённые поиски и подсчёт. Пустой ответ не доказывает отсутствия сообщения: проверьте `coverage.next`
и скачайте недостающую историю перед повторным поиском.

## Разговоры в группе

В оживлённой группе идут сразу несколько разговоров. `max conversations` разбирает их по сохранённым
сообщениям и находит по тому, о чём они были, на этом компьютере: [поиск по темам](topic-search.md).

## Новые сообщения сразу: `max serve` и `max watch`

Обычная команда подключается, делает одно дело и выходит. `max serve` — исключение: он держит одно
подключение к MAX открытым и раздаёт новые сообщения тем, кто слушает.

**Запускать его руками не обязательно.** Первая команда, которой нужен MAX, сама запускает
`max serve` в фоне, если его нет, и работает дальше своим подключением; следующие идут через
сервер. **Такой сервер сам останавливается через 15 минут, если им никто не пользуется.** Что он
пишет — в файле `<профиль>.serve.log` рядом с состоянием профиля (права 600). Не запускать —
`--no-serve` на один раз или `max config set serve false` насовсем. `max session end` сначала
останавливает сервер профиля, если его запустила команда.

**Сервер, запущенный руками (`max serve`, `max server start`), останавливают только Ctrl-C и
`max server stop`**: ни простой, ни `max session end`, ни другие запросы по сокету. Если в фоне
уже работает сервер, который запустила команда, `max serve` руками сменяет его. `--idle` руками —
пожалуйста: это ваш собственный выбор. `max session start` останавливает любой сервер профиля,
входит и запускает его снова уже на новой сессии: подключение к MAX в каждый момент одно.

```sh
max serve                   # вручную, в одном терминале; Ctrl-C — остановить
max serve --idle 30m        # или остановиться, когда им 30 минут никто не пользуется
max server start            # то же, но в фоне; ответ — когда сервер уже подключён
max server status           # работает ли, с какого времени, какой версии, подключён ли к MAX
max server restart          # остановить и запустить снова — например, после обновления max
max server stop             # остановить сервер профиля, как бы он ни был запущен
max server logs             # последние строки его журнала; --lines 200 — больше
max server install          # служба systemd (Linux) или launchd (macOS) для профиля; ничего не запускает
max server uninstall        # убрать службу; сначала max server stop
max watch                   # в другом: новые сообщения по мере прихода
max watch --jsonl           # то же для скрипта: одно сообщение на строку, как у `messages list`
max watch --jsonl | ./on-message.sh
max watch --events --jsonl  # ещё правки, удаления, реакции, прочтения и изменения чатов; у строки поле "event"
```

- **После обновления `max`** сервер, который запустила команда, сменяется новым сам. Запущенный
  руками работает на старой версии, пока его не перезапустить: `max server status` это покажет,
  `max server restart` исправит.
- **Служба вместо команды.** После `max server install` команда `max server start` запускает
  сервер через systemd или launchd, а `max server stop` останавливает его там же. Служба запускает
  `max serve` — сервер «руками», без простоя. Если MAX не принял вход, служба **не** перезапускает
  сервер: каждый повтор был бы новым входом в аккаунт. `max server status` показывает службу и
  где её журнал.
- **Один сервер на профиль.** Второй `max serve` того же профиля откажется. Сокет лежит рядом с
  состоянием профиля, права 600: слушать может только владелец.
- **Что он делает в сети — как вкладка web.max.ru:** пинг раз в 30 секунд, ответ на пинг MAX,
  подтверждение каждого пришедшего сообщения. **Прочитанным он ничего не помечает** и ничего не
  отправляет.
- **Если MAX оборвал связь**, сервер подключается снова: через 1, 2, 4 … секунды, не реже раза в
  минуту. `max watch` пишет об этом в stderr. Если MAX больше не принимает токен, сервер
  останавливается с ошибкой входа.
- **У профиля одно подключение к MAX на всех.** Команды, `max mcp` и `max watch` не входят в MAX
  сами: вход им отдаёт сервер, и всё — чтение, отправка, реакции — идёт через его подключение.
  Защиты отправки срабатывают в самой команде, как раньше. Сервера нет — команда запускает его и
  ждёт; при `serve: false` без сервера команда входит сама. Два сервера на профиль не
  запускаются: второй отказывает, ещё не войдя в MAX.
- Сервер держит свой вход в актуальном состоянии: новое сообщение, чат прочитан на телефоне,
  чат изменился — всё это он учитывает. Если MAX сообщил о том, чего он учесть не может (удалены
  сообщения), сервер в фоне входит заново — не чаще раза в минуту.
- **С `--events` строки другие:** `{"event": "message", "message": …}`, `{"event": "edit", "message": …}`,
  `{"event": "delete", "chatId", "chatTitle", "messageId"}`,
  `{"event": "reaction", "chatId", "chatTitle", "messageId", "reactions"}`,
  `{"event": "read", "chatId", "chatTitle", "userId", "upToTime", "unreadCount"}` — кто-то прочитал чат
  до сообщения с этим временем; это может быть и сам владелец на другом устройстве,
  `{"event": "chat", "chat"}` — у чата сменилось название или участники, или владелец из него вышел.
  Пометка «непрочитанным» событием не считается.
  Без флага вывод прежний — одно сообщение на строку. Кто печатает сообщение, `max watch` не
  показывает: MAX присылает это только клиенту, который держит чат открытым.
- **`max watch` видит только то, что пришло, пока он и сервер подключены.** Пока связь с MAX
  обрывалась, сообщения шли мимо. Строка `status` с `connected: true` после обрыва — сигнал
  добрать пропущенное: `max inbox --since-time <время из поля at предыдущей строки status>`.

## Обслуживание архива

`max store migrate` достраивает индексы; `max store reindex` перестраивает их. `store info` и
`store check` показывают готовность словесного и stem-индексов. Строгий поиск использует основы для форм слов; `exact:` и `--exact` выбирают точную форму. `config set searchStemmers.cyrillic` принимает `russian`
или `none`, `config set searchStemmers.latin` — `english`, `spanish` или оба через запятую (по умолчанию
`english,spanish`: латинское слово ищется по основам обоих языков), либо `none`; `none` отключает
основы для этого алфавита. После своей настройки выполните `store reindex`. Если основы строятся
заново — после обновления `max`, сменившего настройку по умолчанию, — поиск пока ищет точные формы
слов и говорит об этом; `max serve` достраивает основы в фоне, `store migrate` — сразу. Настройка общая для всех профилей и
обоих мессенджеров, поэтому `--defaults`, `--personal` и `--bot` к ней не применяются, а под
`MAX_PROFILE_LOCK` менять её нельзя.

`max store repair --dry-run --json` показывает исправление структуры и откатывает изменения;
`store repair` применяет их без удаления данных. Неподходящая таблица сохраняется как копия,
строки и столбцы, которые не удалось перенести, указаны в ответе. Не удаляйте копию до проверки.
Имена копий есть в ответе `store repair` (`copies` в `--json`); `store copies delete <точное имя>`
удаляет только указанную.
Остановите процессы, использующие архив, перед восстановлением структуры.
