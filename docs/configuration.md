# Настройки

Без файла настроек `max` работает на встроенных значениях. Настройка нужна, когда надоело
повторять флаг или требуется ограничить профиль. Все ключи, значения по умолчанию и переменные —
в [полном справочнике](configuration-reference.md). Формат вывода, ошибки, время выполнения
и правила для агентов описаны в [контракте CLI](cli-contract.md).

## Посмотреть действующие значения

```sh
max config show
max work config show --json
```

Ответ показывает профиль, путь файла, действующие значения и источник каждого значения.
Это чтение настроек: проверка входа выполняется отдельно через `max doctor --online`.
Секретов в файле настроек нет. Токены хранятся в ключнице.

## Изменить настройку

```sh
max config set limit 50
max work config set record true
max config set keepRunsForDays 7 --defaults
max work config unset limit
max shop config set --bot sendsPerHour 200
```

Без флага команда меняет текущий профиль. `--defaults` задаёт значение всем профилям;
`--personal` и `--bot` выбирают раздел личного аккаунта или ботов. `unset` убирает запись:
после этого значение берётся из следующего слоя. Неизвестный ключ или неверное значение
вызывает ошибку до записи файла.

## Как выбирается значение

Флаг на один запуск → переменная окружения → файл → встроенное значение.
Для личного профиля `work` слои файла идут так:
`personal.profiles.work` → `profiles.work` → `personal.defaults` → `defaults`.
У бота вместо `personal` используется `bot`. Профиль важнее общего раздела.

`MAX_PROFILE` выбирает профиль для оболочки; первое слово команды его перекрывает.
`MAX_TIMEOUT` задаёт бюджет команды. `timeoutMs` в файле относится к одному запросу.
Все варианты и исключения перечислены в [справочнике](configuration-reference.md#порядок-в-котором-решается-настройка).

## Права доступа

`permissions` содержит пути команд и уровни `deny`, `readonly`, `ask`, `allow`.
`deny` запрещает действие; `readonly` разрешает чтение; `ask` требует подтверждения;
`allow` выполняет без вопроса. Подтверждение никогда не отменяет запрет.

```sh
max agent config set permissions.messages readonly
max agent config set permissions.messages.send allow
```

Этот профиль читает сообщения и отправляет их, а остальные изменения сообщений запрещены.
Другие ресурсы настраиваются отдельно. У бота ключ начинается с `bot`.
При JSON-выводе вопрос подтверждения не появляется: явный `--yes` отвечает на `ask`,
для удаления используется `--allow-dangerous`. В MCP deny/readonly запрещают запись, а ask/allow допускают запрошенное действие без серверной формы.

Правила наследования, исключения и перевод старых настроек —
[в справочнике прав](configuration-reference.md#права-доступа).

## Где хранится файл

На Linux — `~/.config/max-cli/config.json`. Пути остальных систем описаны в
[установке](installation.md). Команды `config set/unset` работают с файлом за вас;
формат и разделы для ручного изменения — [в справочнике](configuration-reference.md#файл).

Переменные каталогов меняют и запись входа: не смешивайте обычный запуск с запуском
под `MAX_CONFIG_DIR`/`MAX_STATE_DIR`. Общий архив задаёт `MESSAGING_STORE`.
[Отдельные настройки на время](configuration-reference.md#отдельный-набор-настроек-на-время)
позволяют проверить вариант отдельно от обычной конфигурации.

## Настройки общего архива

`searchStemmers.cyrillic` и `searchStemmers.latin` хранятся в архиве и действуют на оба
мессенджера и все профили. После изменения нужен `max store reindex`.
Подробнее — [обслуживание архива](archive.md#обслуживание-архива).
