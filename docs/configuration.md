# Настройки

Эта страница нужна, когда вы снова и снова набираете один и тот же параметр или хотите, чтобы `max`
вёл себя иначе для одного аккаунта. Прочитав её, вы будете знать, где лежит файл настроек, что
делают основные настройки, как изменить одну из них и как проверить, какое значение действует.
Файл для начала работы не нужен: без него у каждой настройки есть встроенное значение.

Слова, которые встречаются на странице:

- **Файл настроек** (`config.json`) — текстовый файл, в котором `max` хранит ваши сохранённые выборы.
- **Профиль** — именованный набор настроек одного аккаунта MAX или одного бота, например `work`.
  Его имя ставится перед командой: `max work chats list`. См. [профили и боты](profiles.md).
- **Параметр** (флаг) — слово, добавленное к одной команде, например `--limit 5`. Он меняет только
  этот запуск.
- **Переменная окружения** — именованное значение, которое терминал или процесс агента передаёт
  `max`, например `MAX_PROFILE=work`.
- **Значение по умолчанию** — то, что `max` берёт, когда ничто другое значение не задало.

## Что можно настроить

Это настройки, которые меняют чаще всего. Точное описание каждой — тип и все способы
переопределения — в [справочнике настроек](configuration-reference.md#файл).

| Настройка | Что делает | Встроенное значение |
|---|---|---|
| `limit` | сколько строк показывает список, если не указан `--limit` | `20` |
| `sends_per_hour` | сколько сообщений профиль может отправить за час; останавливает цикл отправок | `30`; у бота — без лимита, пока не задан в разделе `bot` |
| `requests_per_minute` | как часто `max` обращается к MAX после короткой серии запросов; `0` выключает темп ([ограничения и ожидания](limits.md)) | `20` |
| `permissions` | что профилю можно: только читать, спрашивать перед изменением или делать без вопроса ([права](permissions.md)) | всё разрешено, кроме: удаление и ещё несколько необратимых изменений сначала спрашивают; автоответы не отправляют |
| `record` | записывать каждый запуск, чтобы посмотреть потом ([диагностика](diagnostics.md)) | `false` |
| `record_input` | хранить ли в записи неудачного запуска командную строку так, как вы её набрали; секреты скрыты всегда ([диагностика](diagnostics.md#что-вы-набрали)) | `true` |
| `keep_runs_for_days` | сколько дней хранятся записи запусков | `30` |
| `color` | цвет в таблицах | по терминалу |
| `sender_colors` | свой цвет у каждого автора в списке сообщений | `false` |
| `timeout_ms` | сколько ждать ответа на **один** запрос к MAX, в миллисекундах. Чтобы ограничить команду целиком, используйте `--timeout` | по транспорту |
| `serve` | запускать фоновый сервер `max personal serve`, когда команде нужен MAX ([один вход на всё](limits.md#один-вход-на-всё)) | `true` |
| `transcribe_model` | какой моделью распознавать голосовые сообщения | `gigaam-v3` |
| `update_check` | раз в сутки сообщать, что вышла новая версия `max` | `true` |

Секрета в файле не бывает. В нём нет места для токена, номера телефона или идентификатора чата:
токен хранится в ключнице системы, а где её нет — в файле, который можете читать только вы ([где живёт токен](security.md#где-живёт-токен)).

## Пример файла настроек

Первая команда, которая читает настройки, создаёт начальный файл; `max personal doctor` его не создаёт. Вот он, с одним добавленным
профилем:

```json
{
  "defaults": { "limit": 20, "keep_runs_for_days": 30, "sends_per_hour": 30, "update_check": true, "skill_hint": true },
  "profiles": {
    "work": { "limit": 50 }
  }
}
```

- `defaults` действует для всех профилей.
- `profiles.work` действует только для профиля `work` и важнее `defaults`.

Поэтому `max work chats list` покажет 50 строк, а `max personal chats list` — 20. Добавьте `--limit 5`, чтобы
получить пять строк в одной команде. Уберите `limit` у профиля — и снова действует значение из
`defaults`.

<summary>Полный пример со всеми разделами</summary>

```json
{
  "defaults": {
    "limit": 20,
    "keep_runs_for_days": 14,
    "sends_per_hour": 30,
    "requests_per_minute": 20,
    "update_check": true,
    "skill_hint": true,
    "transcribe_model": "gigaam-v3"
  },
  "profiles": {
    "personal": {
      "limit": 50,
      "color": true,
      "sender_colors": true,
      "record": true
    },
    "work": {
      "permissions": { "messages": "readonly", "messages.send": "allow" },
      "sends_per_hour": 10,
      "serve": false
    }
  },
  "personal": {
    "defaults": { "search_catch_up": true }
  },
  "bot": {
    "defaults": { "permissions": { "bot": "readonly", "bot.messages.send": "allow" } },
    "profiles": {
      "shop": { "sends_per_hour": 200, "read_other_bots": false }
    }
  }
}
```

Что делает каждая часть:

- `defaults`: эти значения получает каждый профиль, если не задал своё. `update_check`, `skill_hint` и
  `transcribe_model` допустимы только здесь: программа и модели речи одни на все профили.
- `profiles.personal`: больше строк, цвета и запись каждого запуска — только для `personal`.
- `profiles.work`: читать сообщения можно, отправлять можно, остальные изменения сообщений
  запрещены. Не больше 10 отправок в час. Фоновый сервер не запускается: каждая команда входит в
  MAX сама.
- `personal.defaults`: только для команд личного аккаунта, никогда для `max … bot`. Здесь
  `messages sync` ещё и готовит скачанные чаты к поиску.
- `bot.defaults`: только для команд бота (`max shop bot …`). Боты могут читать и отправлять, и
  больше ничего.
- `bot.profiles.shop`: бот `shop` может отправить 200 сообщений в час и не читает то, что сохранили
  другие боты на этом компьютере. `read_other_bots` допустим только в разделе `bot`; `serve`,
  `sender_colors` там, наоборот, не принимаются.

</details>

## Где лежит файл

| Система | Путь |
|---|---|
| Linux и macOS | `~/.config/max-cli/config.json` |
| Windows | `%APPDATA%\max-cli\Config\config.json` |

`max config show` печатает путь, который действительно использует этот компьютер, и каждую настройку
со значением. В PowerShell набирайте `max.cmd` вместо `max`. Существующий файл начальным никогда не
заменяется.

## Три способа задать значение

- **В файле:** значение сохранится для следующих команд. `max personal config set limit 50` записывает его.
- **Переменной окружения:** значение действует в одном терминале или одном процессе агента.
  Например, `MAX_PROFILE` выбирает профиль, а `MAX_TIMEOUT` ограничивает время команды.
  Переменная есть не у каждой настройки.
- **Параметром:** `--limit 5` меняет только эту команду.

## Какое значение побеждает?

Параметр важнее переменной окружения. Дальше идёт значение профиля в файле, затем `defaults` в
файле, затем встроенное значение. Настройка участвует только в тех способах, которые она
поддерживает; [справочник настроек](configuration-reference.md#какое-значение-побеждает) перечисляет их
для каждой настройки.

## Изменить значение

Файл можно править в любом текстовом редакторе или поручить это `max`. `config set` проверяет
значение до записи, поэтому никогда не сохраняет файл, от которого откажется следующая команда.

```sh
max personal config set limit 50                 # профилю, с которым вы работаете
max work config set limit 50            # профилю work
max config set sends_per_hour 10 --defaults   # всем профилям
max personal config unset limit                  # вернуть значение по умолчанию
max config show                         # проверить, что действует и откуда взялось каждое значение
```

Опечатка в имени настройки — ошибка, а не тихое значение по умолчанию: каждая команда
останавливается и называет неверный ключ ([опечатки в файле](configuration-reference.md#опечатка--это-ошибка-а-не-умолчание)).

## Профили и боты

Профиль хранит настройки одного аккаунта или одного бота. Его имя ставится перед командой, например
`max work config show`. Чтобы работать от имени бота, а не личного аккаунта, добавьте `bot` после
имени. Как создавать профили и переключаться между ними, объясняет страница
[профили и боты](profiles.md).
