# Группы, которые вы ведёте

`max` помогает админу группы: показывает вопросы, на которые никто не ответил, кто вступил и с
каким аккаунтом, и убирает спам по вашим правилам. По умолчанию он только отмечает — удалить
сообщение или человека он может, только если вы это разрешили.

Всё здесь работает от вашего личного аккаунта и там, где вы админ. Команды подробно —
[usage.md](usage.md#группы-и-каналы), каждая опция — [commands.md](commands.md).

Команды изменения группы в JSON возвращают `operationId`; карточка после создания,
вступления, изменения или замены ссылки находится в `chat`. Если название или описание
успело измениться, а запрос настроек не завершился, результат — `outcome_unknown`.
Прочитайте группу через `chats show` перед повтором: изменение могло примениться частично.

## Сценарии с агентом

Агенту с доступом к терминалу (например, Claude Code или Codex) можно подключить
[навык](../README.md#навык-для-агентов-с-терминалом). Без доступа к терминалу используйте
[MCP-сервер](mcp.md), например в Claude Desktop. В Cursor доступны оба способа. Ниже — ваш запрос,
команда агента и результат.

### Утро админа: кто ждёт ответа

```text
Вы:     Что в «Поход» осталось без ответа?
Агент:  (max review --chat "Поход" --unanswered 4h --json)
        Без ответа больше 4 часов — 3 вопроса:
        · Лена, 08:12 — «Во сколько выезд в субботу?»
        · Артём, вчера 22:40 — ответ на ваш пост про маршрут: «А палатки общие?»
        · Ира, вчера 19:05 — «Кто везёт котелок?»
        На остальные ответили вы или админы.
```

Вопрос — это сообщение со знаком «?» или ответ на ваше сообщение или сообщение админа. Отвеченным
он считается, если вы или админ ответили на него или заговорили первыми после того, кто спросил.
Ссылка со знаком «?» внутри вопросом не считается.

### Новенькие за неделю

```text
Вы:     Кто вступил в «Поход» за неделю? Есть подозрительные?
Агент:  (max chats events "Поход" --type add --json)
        (max chats members list "Поход" --all --json)
        За неделю добавили 4 человек:
        · Катя Смирнова — добавила Лена, аккаунту 3 года
        · Олег — вступил сам, аккаунту 2 дня
        · …
        Стоит посмотреть: Олег — аккаунт совсем новый.
```

### Уборка спама с вашим подтверждением

Один раз настройте правила:

```sh
max chats rules set "Поход" invites delete            # приглашения в чужие чаты — удалять
max chats rules set "Поход" newAccount.days 3         # аккаунт моложе трёх дней — отмечать
max chats rules set "Поход" consent.delete ask        # но перед удалением — спросить меня
```

```text
Вы:     Проверь «Поход».
Агент:  (max_write, command: "chats check")
        Найдено приглашение. Правила требуют отдельного согласия: действие оставлено планом.
        Для выполнения в терминале: max chats moderate "Поход" --allow-dangerous --json
Вы:     Выполняю эту команду.
```

В терминале `max chats moderate "Поход"` задаёт тот же вопрос сам: `[y/N]`.

### Недельный отчёт по группе

```text
Вы:     Сделай итог недели по «Поход».
Агент:  (max review --chat "Поход" --since-time 2026-09-20T00:00 --json)
        Решили: выезд 4 октября, в 7:00 от метро.
        Взяли на себя: Лена — продукты, Артём — палатки.
        Висит: кто везёт котелок — спросили трижды, ответа нет.
```

### Проверка по расписанию

Агент не нужен: проверка — обычная команда. Два раза в день, с удалением там, где правило стоит на
уровне `ask`:

```cron
0 9,21 * * * max chats moderate "Поход" --allow-dangerous >> ~/max-check.log 2>&1
```

Без `--allow-dangerous` в cron действия уровня `ask` только планируются и ждут вас. Строки
`PATH` и `XDG_RUNTIME_DIR`, без которых `max` в cron не найдёт Node и ваш вход, —
[recipes.md](recipes.md#как-запускать-по-расписанию).

## Что можно

| Команда | Что делает |
|---|---|
| `max review --chat <чат> --unanswered [длительность]` | вопросы, на которые вы и админы не ответили за указанное время (например, `4h`; по умолчанию `24h`) |
| `max chats events <чат>` | кто вступил, вышел, кого добавили и удалили, кем; по умолчанию за 7 дней |
| `max chats members list <чат>` | страница участников от MAX (`--all` — все доступные, до 5000): кто владелец и админы (сразу после `admins add` роль может быть прежней), когда заведён аккаунт, когда был в сети |
| `max chats rules show\|set\|unset <чат>` | правила группы |
| `max chats moderate <чат>` | проверка по правилам; делает то, что правила разрешают |
| `max chats members add\|remove`, `admins add\|remove` | участники и админы |
| `max chats link show\|reset <чат>` | ссылка-приглашение; `reset` — новая, старая перестаёт работать |
| `max chats update` | настройки, название, описание; прочитать настройки — `max chats show` |
| `max messages delete --for-everyone`, `pin`, `unpin` | удалить у всех, закрепить |

Агенту без терминала то же самое дают инструменты MCP: `max_read` (`command: "review"`) с `unanswered_after_hours`,
`max_read` (`command: "chats events"`), `max_read` (`command: "chats members"`), `max_read` (`command: "chats rules"`) и `max_write` (`command: "chats check"`)
([mcp.md](mcp.md)).

## Что ждёт вашего ответа

`max review` ведёт в локальной копии список задач; `max serve` в MAX задачи пока не открывает. Вопрос, на который никто не ответил, и
сообщение, где вас упомянули по имени, открывают задачу; ваш ответ её закрывает. Задача ссылается на
сообщение и не копирует его текст.

```sh
max tasks list --state open                               # что ждёт ответа, старые сверху
max tasks list --chat "Поход" --type question,mention
max tasks add msg:max/<вы>/<чат>/<сообщение> --type promise   # то, чего правила не видят
max tasks close <задача> --as dismissed --reason no-reply-needed
max stats tasks show                                           # открытые по чатам, самая старая, медиана до закрытия
```

Закрытая задача остаётся закрытой, отклонённая не возвращается. Задачу закрывает только ваш ответ —
ответ админа пока нет, — а упоминание через `@ник` не замечается. Агенту то же самое дают
инструменты MCP: `max_read` (`command: "tasks list"`), `max_write` (`command: "tasks add"`), `max_write` (`command: "tasks close"`), `max_read` (`command: "stats tasks show"`) ([mcp.md](mcp.md)).

## Правила

Правила хранятся на вашем компьютере, у каждой группы свои. Первое `set` записывает все правила
сразу, со значениями по умолчанию.

| Правило | По умолчанию | Что значит |
|---|---|---|
| `trusted` | — | номера людей через запятую; правила их не трогают |
| `blocked` | — | номера людей, чьи сообщения и вступление ловятся |
| `blockedNames` | — | части имени, через запятую, без учёта регистра |
| `blockedPeople` | `report` | что делать с сообщением или вступлением заблокированного |
| `invites` | `report` | приглашение в другой чат (`max.ru/join/…`, ссылки Telegram) |
| `links` | `report` | любая ссылка |
| `forwards` | `report` | пересланное сообщение |
| `flood.messages`, `flood.minutes`, `flood.action` | 5, 1, `report` | больше 5 сообщений за минуту от одного человека |
| `newAccount.days`, `newAccount.action` | 7, `report` | аккаунт моложе 7 дней; 0 выключает |
| `consent.delete`, `consent.remove` | `ask` | насколько вы разрешаете каждое действие |

Действие правила — `report` (отметить), `delete` (удалить сообщение у всех) или `remove` (удалить
человека из группы). Если сообщение нарушает несколько правил, берётся самое сильное действие.
Вас, админов и людей из `trusted` правила не трогают.

Уровень согласия решает, будет ли действие сделано:

- `deny` — никогда;
- `readonly` — только отметить;
- `ask` — спросить в терминале; без ответа действие ждёт. `--allow-dangerous` разрешает такие
  действия для этого запуска;
- `allow` — сразу.

Старые файлы читаются: `forbid` становится `deny`, `flag` и `confirm` — `ask`.
MCP вызывает `max_write` с `command: "chats check"`; действия при уровне согласия `ask`
остаются планом, серверных форм нет.

`chats moderate --json` возвращает `{ chatId, rows }`. `--since-time` принимает время ISO 8601
или `30m`, `2h`, `1d`, а не номер сообщения, и не сдвигает сохранённое место.
Место следующей проверки хранится вместе с правилами; старое место из сессии переносится
автоматически перед первым запуском. CLI и личный MCP используют одно место.

## Через бота

Если в группе есть ваш бот с правами админа, ту же проверку может делать он: `max <бот> bot chats
moderate`. Он умеет то, чего не умеет личный аккаунт, — банить удалённых, чтобы они не вернулись по
ссылке. Возраст аккаунта ему недоступен. Подробно — [bot.md](bot.md#проверка-чата-по-правилам).

## Ограничения

- **Бана нет.** Удалённый человек может вернуться по ссылке-приглашению: личный аккаунт не умеет
  банить. Замените ссылку (`max chats link reset`) или проверяйте группу ботом — он банит.
- **Заявок на вступление нет.** В MAX группа либо открытая, либо в неё входят по ссылке-приглашению;
  одобрять новых участников нельзя.
- **Не больше 10 действий за проверку** (`--max-actions`). Удаления считаются в лимит отправок в
  час; упёрлась в лимит — остальное ждёт следующей проверки.
- **До 1000 сообщений за проверку в CLI.** Если их больше, следующая проверка продолжит с того места.
- **Одно вступление — весь список участников.** Чтобы узнать возраст аккаунта новенького, проверка
  читает список участников целиком; в большой группе это десятки запросов к MAX.
- **Ничего не следит за группой само.** Проверка идёт, только когда её запустили вы, агент по
  вашей просьбе или ваше расписание.

## Статистика для админа группы

`max stats chats show` считает сообщения, активных отправителей, ответы, ветки, реакции и вопросы с ответами
за выбранный период из локального хранилища. `--by day` или `--by week` добавляет разбивку по календарным
дням или неделям; неделя начинается в понедельник, `--timezone` задаёт часовой пояс.
Просмотры постов канала появляются, только если MAX передал их и они сохранены вместе с сообщениями.
Отсутствующее число не означает ноль. Реакции считаются по сохранённым данным, а не запрашиваются заново
для каждого поста. Вопросы определяются так же, как в `review --unanswered`.

Обычный запуск дополнительно читает события вступления и выхода из MAX. В `--offline` эти события
не запрашиваются, поэтому поле `members` отсутствует. Оно отличается от `memberCounts`: это сохранённые
ежедневные снимки числа участников, которые доступны и без сети.

Если `complete` — `false`, данные неполные: суммы отражают только доступную историю, а медианы и доли
могут отличаться от итогов по всей группе. Поле `fetch` подсказывает команду для загрузки недостающих
сообщений. Неполная история событий тоже ограничивает число вступлений и выходов. Даже полная история
сообщений не восстанавливает прежние профили участников и их списки за дни до начала сбора.

### Снимки участников

`max chats members fetch` читает участников в локальное хранилище: сохраняет их профили, изменения,
число участников за день и результат проверки полноты. `--budget` ограничивает число страниц.
При неполном списке никто не записывается как вышедший: для этого нужен весь доступный список и
известное число участников группы, не превышающее число прочитанных. В MAX списки часто частичные;
увеличение бюджета помогает только там, где сервер действительно отдаёт остальные страницы.

`chats tracking add` добавляет группу в список отслеживания. `chats tracking list` показывает этот список,
`show` — состояние группы и снимки числа участников за последние 30 дней, `add` не читает участников
немедленно, `remove` прекращает отслеживание и сохраняет накопленную историю.
**В MAX `serve` пока не собирает эти списки ежедневно.** Повторяйте `chats members fetch` вручную или
по своему расписанию; само добавление в tracking не запускает сбор.

`max chats members history` показывает сохранённые вступления, выходы и изменения профиля в порядке
времени; `--since-time` ограничивает период. Команда не обращается к MAX. Время вступления берётся
из ответа MAX, если оно известно, иначе это первое обнаружение человека. Время выхода — первый полный
снимок без него, а не точный момент ухода. Первое чтение создаёт исходный состав: эти люди не обязательно
вступили в день чтения. `chats members list --offline` показывает последний полностью сохранённый
состав: частичные чтения не заменяют его. Если полного снимка ещё не было, этот список может быть пустым,
хотя отдельные профили и события уже сохранены.
Профили и история остаются в локальном хранилище рядом с сообщениями.

`max chats members audit` читает участников и показывает признаки подозрительных аккаунтов.
`--budget` ограничивает страницы, `--min-score` — минимальную оценку. Это подсказка для проверки человеком:
никто не удаляется, админы и владелец исключены; `more` означает неполный список, `unknown` — неизвестные
признаки. MAX не предоставляет все признаки Telegram. С `--offline` проверка недоступна.
«Не писал» означает, что сообщения человека не найдены в локальной истории; это не доказательство,
что он никогда не писал в группе.

`--deep <n>` дополнительно проверяет первых n участников полностью, по одному в секунду: профиль и до 1000
сохранённых сообщений каждого. Публичные списки спамеров ведут только аккаунты Telegram, поэтому для MAX
они не запрашиваются, и в ответе это сказано.

### Недельный отчёт по своей группе

«Поход» ниже — вымышленная группа для примера. Сначала загрузите её сообщения через `store fetch`,
если их ещё нет в хранилище, затем сохраните текущий состав и подготовьте отчёт:

```sh
max chats tracking add "Поход" --json
max chats members fetch "Поход" --json
max stats chats show "Поход" --since-time 7d --by day --timezone Europe/Madrid --json
max chats members history "Поход" --since-time 7d --offline --json
max chats tracking show "Поход" --offline --json
max chats members audit "Поход" --json
```

Попросите агента указать число сообщений и активных отправителей, вопросы без ответа, изменения состава
и дни со снимками участников. В отчёте должны остаться признаки неполноты: `complete`, `more`, `unknown`
и отсутствие снимков за отдельные дни. Для следующего отчёта повторяйте сбор участников; первый отчёт
не может показать выходы, которые произошли до первого сохранённого состава.
