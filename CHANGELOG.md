# Изменения

Заметные изменения в `@leemour/max-cli`. Формат — по одному разделу на версию, новое сверху;
номера версий по [семантике](https://semver.org/lang/ru/), то есть до `1.0.0` интерфейс команд
ещё может меняться.

## Не выпущено

### Что нового

- **`max skill show link-conversations` печатает общий навык связывания разговоров.**
  Команда доступна без сессии; без имени по-прежнему выдаётся основной навык MAX.

- **`max messages evidence` выдаёт ограниченный пакет из локального архива**, с locator,
  сведениями о полноте и продолжением через `--before-id`. Команда не подключается к MAX.

### Изменено — может сломать скрипты

- **`max sends list` учитывает настроенный `limit`, как Telegram.** Раньше без флага всегда
  выбирались 20 попыток. Поле JSON `limit` содержит выбранный предел;
  `items`, `page`, `hasMore` сохраняются. `--limit` имеет приоритет над настройкой.

- **`max messages download` поддерживает `--all`, `--output-dir` и `--pause`, как Telegram.**
  Каталог создаётся автоматически; повторный обход всего чата продолжает сохранённый прогресс.
  `--output` остаётся совместимым именем каталога. JSON одного сообщения теперь содержит `{items}`,
  без искусственных `page`, `limit`, `hasMore`; скриптам следует читать `items`.
  Файлы скачиваются потоком с прежними проверками адресов и размера, без ограничения голосовых в 32 MiB.

## 0.25.0 — 03.10.2026

### Что нового

- `bot api` использует общий с Telegram конструктор команд и проверку входных данных.
  Генераторы остаются в cli-core; параметры, нативные ответы и действующие разрешения MAX
  сохранены. Общая опция `--store-token <profile>` предназначена для операций, возвращающих
  учётные данные; остальные операции её отклоняют.

### Изменено — может сломать скрипты

- **`max models audio list --json` добавляет `directory`:** общий каталог моделей, который
  используют MAX и Telegram. Команды моделей, каталог и проверка скачивания теперь общие;
  существующие файлы, порядок моделей и настройка `transcribeModel` сохраняются. Повторно
  скачивать модели не нужно. JSONL по-прежнему выдаёт одну модель на строку.

- **`--md` разбирает собственный форматтер MAX** для send/edit и подписей: вложенные стили, `__жирный__`, `++подчёркнутый++`, ссылки и код. Боты поддерживают выделение, заголовки и цитаты через безопасный HTML; личный протокол явно отказывает неподтверждённым типам. Telegram имеет другой синтаксис. Неизвестные wire-типы больше не отправляются молча.

## 0.24.0 — 03.10.2026

### Что нового

- **`max setup` проводит через первый запуск личного аккаунта:** проверяет локальные каталоги,
  предлагает QR-вход, проверяет аккаунт и до пяти чатов и подключает навык выбранного агента.
  Повторный запуск использует существующую сессию. История скачивается отдельно; setup не
  запускает фоновый сервис. Справка, установка и инструкция для агента объясняют следующие шаги
  и запуск на Windows без PATH. `max skill show` доступен до входа.

### Изменено — может сломать скрипты

- **`max chats check` заменён на `max chats moderate`:** общие правила и модерация с Telegram.
  `--since-time` принимает время или `30m`/`2h`/`1d`, вместо прежнего `--since` с номером сообщения;
  JSON теперь `{ chatId, rows }`. За запуск читается до 1000 сообщений.
  Уровни правил — `deny|readonly|ask|allow`; старые `forbid` и `flag|confirm` читаются как `deny` и
  `ask`. Сохранённое место проверки переносится из сессии в прежний файл правил, поэтому первый
  запуск продолжает с него. CLI и личный MCP используют одно место; имена MCP-инструментов
  и их флаги сохранены. Событие вступления по ссылке в `chats events` называется `join`.

- **`max upgrade --json` всегда содержит список `restarted`.** В MAX это пустой массив:
  политика запуска серверов при обновлении сохранена. Проверка версии и отсутствие обновления
  возвращают ту же форму ответа, что установка; прежние поля остаются. Скриптам с точной проверкой
  набора ключей нужно учесть добавленное поле.

- **Локальный поиск использует строгий профиль Lucene:** скобки, поля, диапазоны дат и
  `--timezone`, ограниченные шаблоны и regex. Префикс задаётся явно как `слово*`; прежний
  поиск с исправлениями доступен через `--language legacy`. JSON сообщает охват даже без
  результатов. Руководство и навык описывают миграцию; JS `--regex` выполняется в отдельном
  worker с пределами размера и времени.

- **`max commands --json` возвращает версию JSON-контракта в поле `contract`.** Значение `0`
  совпадает с Telegram CLI; прежние поля справочника сохранены. Скриптам, сравнивающим весь JSON
  с сохранённой строкой, нужно учесть новое поле; выбор отдельных полей менять не требуется.

- **Чтения групп используют общие опции и форматы.** `chats events` принимает `--since-time`
  вместо `--since` и `--type` вместо `--event`; граница — время, а не id сообщения. Событие
  создания теперь называется `create` вместо `new`. `chats members list` показывает страницу
  с `--limit`, `--page` и `--all`; для прежнего объёма добавьте `--all`. JSON больше не содержит
  `chatId` и `rolesKnown`, но роли, даты регистрации и последнего посещения остаются в строках.
  `chats inspect` возвращает `id`, `kind`, `title`, `username`, `participantsCount`, `description`
  и `member` вместо карточки с доступом, ссылкой и настройками. `member` и `username` равны
  `null`, когда MAX их не сообщает. Это единые чтения MAX и Telegram; обновите скрипты и фильтры.
  Предупреждения о неполном списке и неизвестных ролях сохраняются; никакое чтение не отмечает
  сообщения прочитанными. Подробнее: [группы](docs/usage.md#группы-и-каналы).

- **Команды управления группами отвечают общим JSON с `operationId`.** `chats create`, `join`,
  `update` и `link reset` кладут карточку в `chat`; `leave` возвращает `chatId`. У `members add`
  теперь поля `added` и `notAdded`, у `members remove` — `removed`; у команд `admins` —
  `personId`, а при добавлении ещё и `rights`. Это единый формат операций MAX и Telegram;
  скриптам нужно обновить разбор результата. `link show` сохраняет прежний формат.
  Название и настройки по-прежнему меняются двумя запросами: если название или описание
  уже изменено, а запрос настроек не завершился, команда сообщает `outcome_unknown` и
  отмечает неполный результат в журнале. Прочитайте `chats show` перед повторной попыткой.
  Подробнее: [управление группами](docs/usage.md#группы-и-каналы).

- **`max account update` и `max account sessions end` возвращают общий формат с `operationId`.**
  Изменение профиля отвечает `{operationId, account}` с полями `id`, `name`, `username`, `phone`,
  завершение сеансов — `{operationId, sessions}` вместо массива. Это единый формат операций
  MAX и Telegram; скриптам нужно читать данные из `account` либо `sessions`. Описание профиля
  больше не возвращается после изменения: его показывает `account show`. Номер телефона
  остаётся замаскированным; `sessions end` по-прежнему требует `--others --yes`.
  Для фото профиля теперь принимаются JPG, JPEG, PNG и WebP; GIF нужно преобразовать в один
  из этих форматов. Подробнее: [профиль и сеансы](docs/usage.md#контакты-профиль-папки).

- **`max chats folders create|update|delete` возвращают `operationId` вместе с результатом.**
  Создание и изменение отвечают `{operationId, folder}`, удаление — `{operationId, folderId}`,
  вместо самой карточки папки. Это общий формат операций MAX и Telegram; скриптам нужно
  читать карточку из `folder` и использовать `folderId` после удаления. `update` без `--title`,
  `--add` или `--remove` теперь отказывается вместо повторной записи той же папки.
  Список папок сохраняет прежний формат. Подробнее: [папки](docs/usage.md#контакты-профиль-папки).

- **`max contacts add|remove|block|unblock|rename|import` возвращают общий формат с `operationId`.**
  Добавление и переименование отвечают `{operationId, person}`, удаление и блокировка —
  `{operationId, personId}`, импорт — `{operationId, sent, recognised}`. В `recognised` теперь
  карточки людей (`id`, `name`, `username`), которые MAX вернул, вместо номеров телефонов; если
  карточек нет, список пуст. `sent` считает строки файла, включая повторяющиеся номера.
  Это единый формат операций MAX и Telegram; скриптам нужно обновить разбор ответа.
  Ошибка номера, отклонённого MAX, больше не указывает строку файла; ошибка структуры строки
  по-прежнему указывает её номер. Подробнее: [контакты](docs/usage.md#контакты-профиль-папки).

- **Команда `max cache clear` удалена.** Все чтения и имена используют общую локальную копию;
  `max store clear --left --allow-dangerous` удаляет данные покинутых чатов. Удаления всей общей
  копии команда не предлагает. Старый файл не переносится и не открывается; его путь показывает
  `max doctor`, а историю можно заново скачать через `max store fetch`.

### Исправлено

- **`max conversations embed status` точнее оценивает время для e5-small.** Расчёт использует
  измеренные 31 фрагмент/с вместо 15; на ноутбуке из измерения прежняя оценка была вдвое длиннее.
  Реальное время зависит от компьютера и длины текста. Три рабочих потока дают измеренные
  1,04–1,1× при заметном расходе памяти; распределение потоков не менялось.

- **`max_messages_search` через MCP сохраняет сведения об охвате архива и использует параметры
  того же поиска, что CLI.** Доступны `language`, `timezone`, versioned `ast`, имя чата и фильтры
  `source`, `newest`, `context`. Запрос из одного символа допускается стандартным профилем.
  Раньше часть параметров отсутствовала, а ответ терял `query`, `coverage` и `completeness`;
  пустая выдача не объясняла охват локальной копии. Прежние поля ответа и имя инструмента сохранены.

- **`max runs list --limit` предлагает увеличить лимит, если показаны не все записи.**
  Подсказка не предлагает отсутствующую опцию `--page`. Чтение списка и отдельной записи
  не создаёт нового запуска; JSON-список по-прежнему содержит `hasMore`.

- **`chats show` показывает записанную группу, даже если её нет в последней дельте входа.**
  Раньше чтение могло закончиться ошибкой «нет чата». Неизвестные настройки и ссылка теперь
  остаются пустыми; чтение ничего не меняет в группе.


- **`max messages transcribe` находит сохранённую расшифровку и по имени чата, когда модель не скачана.**
  Раньше команда искала текст по введённому имени вместо id чата и предлагала скачать модель заново.
  Полное имя и его однозначный фрагмент теперь возвращают сохранённый текст без скачивания записи
  и повторного распознавания. Подробнее: [голосовые сообщения](docs/usage.md).

- На Windows генератор использует Node вместо прямого запуска `.cmd`; проверки документации
  распознают пути Windows. Тесты Unix-прав не требуют их от Windows, где доступ задаётся ACL.

- **Ошибки `max bot` до запуска действия учитывают настройки записи bot-профиля,
  даже если перед командой указан `--timeout`.** Раньше при глобальной опции перед `bot`
  могли применяться настройки личного аккаунта. Если запись выключена для bot-профиля,
  ошибка разбора команды теперь не создаёт запись вопреки этой настройке.

## 0.23.0 — 03.10.2026

### Что нового

- **`max serve` и команды управления чатами сохраняют имена и чаты в общей локальной копии.**
  Старый кэш профиля больше не открывается. Полный список отмечает покинутые чаты;
  пустой ответ сохраняет предыдущий список.

- **Команды контактов и общие команды чтения сохраняют данные в общей локальной копии.**
  Поиск человека по имени и `contacts sync` больше не требуют старого кэша профиля; синхронизация
  по-прежнему возвращает только счётчики. Удаление старого файла не сбрасывает точку синхронизации;
  чтобы получить полный список заново, выполните `max contacts sync`.

- **`max mcp` отпускает модель поиска через 10 минут без поиска** — `conversations_search` у агента
  больше не держит около 1 ГБ памяти всю сессию. Следующий поиск загрузит модель снова, примерно за
  секунду (cli-messaging 0.110.0).
- **Автодополнение чатов и людей берёт подсказки из общего хранилища выбранного аккаунта.**
  Старый кэш больше не нужен. Tab по-прежнему не подключается к MAX; команды бота предлагают
  чаты из своего локального списка.
- **`max mcp setup codex|claude-code` и `max mcp doctor`** добавляют локальный MCP в выбранный
  клиент и проверяют запуск и список инструментов. Если профиль предлагает запись, установка
  требует `--allow-writes`; это подтверждение не меняет права и не проверяет вход в MAX.
- **`max <бот> bot store fetch <чат>`** — скачать историю чата в локальную копию бота, новые сначала;
  повторный запуск продолжает. `--last`, `--since-time`, `--limit`, `--page-size`, `--pause` — как у
  `max store fetch`.
- **`--yes` для любой команды** — согласие на вопрос, который уровень `ask` задаёт перед записью;
  `max account sessions end --others --yes` работает как раньше.

### Изменено — может сломать скрипты

- **`messages send --topic` и `polls create --topic` возвращают понятный отказ для MAX.**
  Это общая опция адресации тем Telegram, которых MAX не поддерживает; сообщение или опрос
  при таком вызове не отправляется. Обычные вызовы без `--topic` работают как прежде.

- **`max doctor --json` сообщает об общем хранилище в `store`, а старый файл — в `legacyCache`.**
  Проверка больше не открывает старую локальную копию и не проверяет её схему.
  Скриптам, которые читали `cache`, нужно перейти на `store`; старый файл можно удалить вручную,
  а историю снова получить через `max store fetch`.
- **MCP читает общую локальную копию сообщений.** Поиск, контакты, ресурсы чатов и расшифровки
  используют `messages.db` под аккаунтом профиля; отдельный кэш профиля больше не открывается.
  Чтение истории сохраняет сообщения для последующего поиска. Голосовые вложения в ответах
  чтения имеют `kind: "voice"`. Имена инструментов и их параметры прежние.
- **`inbox` и `review` используют общий формат команд и сообщений.** Вместо `--since` укажите
  `--since-time`; `review --unanswered` принимает длительность с единицей (`4h`, `1d`), а не число
  часов. Голосовые вложения в JSON имеют `kind: "voice"` вместо `"audio"`; есть `--all` для тихих и
  архивных чатов. Проверка входящих переносит прежнюю точку `inbox --new` при первом запуске.
  Обзор читает историю страницами назад и показывает не больше 300 сообщений на чат, отмечая
  неполный результат. Обновите команды в скриптах и проверки JSON.
- **Расшифровки личного аккаунта сохраняются в общей локальной копии сообщений.**
  `messages transcribe`, `inbox`, `review` и MCP используют тот же текст, что `messages list`,
  под тем же аккаунтом. Старые расшифровки из отдельного кэша профиля не переносятся: при следующем
  явном запросе с `--transcribe` они создаются заново; модель должна быть скачана.
- **`max <бот> bot people show` теперь `max <бот> bot contacts show`**, инструмент MCP —
  `max_bot_contacts_show`. Вместе с `bot messages search|between` команды общие с `tg`; опции и ответы
  прежние.
- **`max <бот> bot chats check` теперь `max <бот> bot chats moderate`** — имя и команда общие с
  `tg`. `--since` теперь `--since-time` (ещё принимает `2h`, `1d`); ответ `--json` — `{ chatId, rows }`
  вместо списка; инструмент MCP — `max_bot_chats_moderate`. Правила и точка прошлой проверки остались в
  тех же файлах. Уровень согласия `flag` теперь значит то же, что `confirm`: спросить вас, а с
  `--allow-dangerous` — сделать.
- **`max <бот> bot mcp` даёт агенту то, что разрешает профиль бота**, а не флаги. Без флагов агент
  теперь может и писать от имени бота, если у профиля нет `readOnly: true` или `allow`; удаление —
  после вашей формы, `--allow-dangerous` её убирает. `--allow-send`, `--allow-delete` и
  `--allow-moderate` принимаются с предупреждением и ничего не решают. Чтобы осталось только чтение,
  поставьте профилю бота `readOnly: true`. Сервер теперь общий с `tg`.
- **`max bot messages search` ищет по словам, лучшие совпадения сверху** — раньше искал кусок текста
  и показывал новые сверху; прежний порядок — `--newest`. Нужны все слова; работают `"фраза"`, `-слово`,
  `а OR б` и фильтры `from:`, `chat:`, `after:`, `before:`, `has:`; опечатка исправляется (об этом —
  строка в stderr). Слова можно писать без кавычек. `--from` по-прежнему можно повторять. `in:` в
  поиске бота не работает: бот ищет только в своей копии и в копиях, разрешённых `readOtherBots`.

### Исправлено

- **При отказе в записи бот называет действующую команду настройки с `--bot`.** Если профиль
  только для чтения, подсказка предлагает выключить `readOnly`; если действие отсутствует в `allow`,
  предлагает добавить его, сохранив уже разрешённые действия. Раньше называла несуществующий `bot config`.

## 0.22.0 — 02.10.2026

Большая часть команд личного аккаунта теперь общая с tg: те же опции, те же ответы `--json`, одна
общая локальная копия. Поэтому многое переименовано — смотрите «Изменено — может сломать скрипты».
Прежняя локальная копия max в общую не переносится: после обновления запустите команды без
`--offline`, а историю скачайте заново через `max store fetch`.

### Что нового

- **`max conversations search "<запрос>"`** — разговоры, близкие по смыслу, в одном чате или во всех.
  Сначала один раз `max models text download e5-small` (135 МБ, общая папка с `tg`), потом
  `max conversations embed --chat <чат>` считает векторы на этом компьютере; `embed status` — сколько
  осталось, `embed clear` — стереть. С `--provider openai` и своим ключом (`max models text key set
  openai`) векторы считает внешний сервис — `embed` сначала называет число токенов и цену и ждёт «да».
- **У личного чата в `chats list --json` есть `providerMetadata.partnerId`** — id собеседника. По нему общие
  команды узнают человека за личным чатом: у MAX id чата и id собеседника разные.
- **`max messages search` ищет и в других аккаунтах общей копии**: `in:max`, `in:personal`,
  `in:bots`, `in:all` в запросе или `--source`. Без них — как раньше, в аккаунте, от которого
  запущена команда.
- **`max conversations build|list|show` и `max messages links`** — разговоры внутри группы, найденные в
  локальной копии по ответам, упоминаниям и тому, кто написал следом; MAX не спрашивается. **`conversations
  batches status|next` и `conversations links add|clear`** — пачки для вашего агента и его ответы.
- **`max server logs`, `max server install`, `max server uninstall`** — как в tg. `install` пишет службу
  systemd (Linux) или launchd (macOS) для профиля и ничего не запускает; дальше `max server start`
  и `stop` идут через неё. Если MAX не принял вход, служба сервер не перезапускает: каждый повтор
  был бы новым входом в аккаунт. `max server start --idle` и `restart --idle` остаются.
- **`max store status`** — сколько сообщений каждого чата хранится и какие куски скачаны целиком.
  **`store fetch --background`** и **`store jobs list|show|cancel`** — скачивание в фоне.
  **`store info|check|migrate|backup|restore|reindex`** — уход за файлом общей копии. **`store clear --left
  --allow-dangerous`** удаляет из неё чаты, из которых вы вышли, с их сообщениями.
- **`max bot auth`, `max bot list`, `max bot chats list`, `max bot recipients` и `max bot sends list`
  теперь общие с tg** (cli-messaging): ответы и подсказки те же. Токен, список получателей и журнал
  лежат там же, где лежали.
- **`max cache clear --left`** стирает из локальной копии профиля только чаты, из которых вы вышли,
  вместе с их сообщениями. Остальная копия не трогается.
- **`max messages search --regex`** — одно регулярное выражение по всему сохранённому тексту.
  **`messages show|context msg:…`** — сообщение по ссылке из `search`, без id отдельно.
- **`max polls show <чат> <сообщение>`** — опрос с id вариантов и числом голосов, ничего не меняя.
- **`max polls create --send-id`** — повторить создание опроса, ответ на которое не пришёл, без
  второго опроса.
- **`max messages send --photo <путь>`** — отправить `.jpg .png .webp` фотографией, как в tg.
  `--no-preview` у `send` тоже есть, но MAX его не поддерживает, и команда откажет.
- **`max skill install`** ставит навык для агентов одной командой: в `~/.claude/skills/max-cli/`
  для Claude Code и в `~/.agents/skills/max-cli/` для Codex и Gemini CLI, с номером версии `max`.
  `--for claude` или `--for agents` — только в одну папку. `max skill show` печатает то же, что раньше.
- **Агент узнаёт о навыке сам.** Если задана переменная `AI_AGENT` или `CLAUDECODE`, а навыка нет
  или он старше `max`, раз в сутки в stderr выходит одна строка про `max skill install`. В stdout
  ничего не добавляется. Выключается `max config set skillHint false --defaults`.
- **`max mcp` и `max bot mcp` отдают навык ресурсом `max://skill`** и называют его в своих
  инструкциях для агента.
- **`max messages delete` отвечает с `operationId`** — номером этого удаления; тот же номер стоит в
  журнале отправок (`max sends list`). Инструмент MCP `max_messages_delete` отвечает так же. Сама
  команда и её опции не меняются.
- **У каждой записи в журнале отправок есть `operationId`** — номер одного действия. Все строки об
  одной отправке, правке, удалении или изменении чата несут один и тот же номер, так что по нему
  видно, чем действие кончилось. У отправки сообщения это её `sendId`.
- **Установка легче примерно на 16 МБ**: слой базы данных теперь встроен в пакет, а не ставится
  отдельно. Команды `max` не меняются.

### Изменено — может сломать скрипты

- **`max messages search` ищет по словам, лучшие совпадения первыми** — раньше самые новые первыми,
  теперь для этого `--newest`. В запросе работают `"фраза"`, `-слово`, `OR` и фильтры `from:`, `chat:`,
  `after:`/`before:` и `has:`. Опечатка исправляется, и об этом пишется в stderr. `--context <n>`
  показывает сообщения вокруг каждого совпадения. В JSON у каждого совпадения появились `match` и `score`.
- **`max bot updates watch` теперь `max bot watch`**, как в tg и как личный `max watch`. Без `--events`
  печатаются только новые сообщения, с `--events` — всё, и каждая строка называет своё событие
  (`{ "event": "message" | "edit" | "delete" | "callback" | "joined" | … }`) вместо сырого события MAX.
  `--timeout` завершает его обычным образом, с кодом `0`. Профилю бота «только чтение» `watch` теперь
  разрешён: получать события — это чтение. Отметка, с которой продолжать, осталась прежней.
- **`bot webhooks list` отвечает `{ url, types }`**, а не полями MAX. `bot callbacks answer --text`
  больше не читает текст из stdin по `-`. `bot commands`, `bot callbacks` и `bot webhooks` теперь
  общие с tg; секрет `webhooks set --secret-stdin` спрашивается только после проверки прав.
- **Нужен Node 22.16 или новее** (или Bun, как раньше). Если Node на Linux взял системный SQLite,
  а тот слишком стар для локальной копии, `max` перезапускается на своём SQLite из
  `@leemour/cli-messaging-sqlite` до того, как что-то прочитать или отправить. Официальные сборки
  Node и Bun ничего не замечают.
- **`max store` — общая группа команд tg и max.** `store fetch` пишет в общую локальную копию, ту же,
  что у tg, и листает MAX как раньше: по 30 сообщений, 5–10 с между страницами, до 40 страниц за
  запуск.
  Почему: одна копия и одни команды для обоих мессенджеров; `messages`, `conversations` и `store`
  читают одно и то же.
  Что учесть: копия, которую max вёл раньше, не переносится — историю скачайте заново. Кроме того:
  - `store fetch --estimate` для MAX отказывает: id сообщений MAX не позволяют сосчитать, сколько
    не хватает;
  - `store fetch|export --since` теперь `--since-time`, и только время, не id сообщения;
  - `store fetch --max-pages <n>` теперь `--limit <сообщений>` (по умолчанию 1200, то есть 40 страниц
    по 30); размер страницы — `--page-size`;
  - `store export --format md` теперь `--format markdown`; `jsonl` как был. Выгрузка больше не
    перечисляет в stderr куски, которых нет в копии, — их показывает `store status`; существующий
    файл она не перезаписывает;
  - `store fetch` в конце не печатает готовую команду выгрузки.
  - если два сообщения отправлены в одну и ту же миллисекунду и граница страницы прошла между ними,
    `store fetch` может пропустить более раннее из них. Это редкость.
- **`max messages list|show|context|search` — общие команды tg и max.** `--offline` и `search`
  отвечают из общей локальной копии, той же, что у tg.
  Почему: те же опции и ответы, что у tg, и одна копия для чтения.
  Что учесть: инструменты `max mcp` для чтения сообщений и чатов пока читают прежнюю копию max, так
  что агент через MCP и команда в терминале с `--offline` могут ответить по-разному. Копия заполняется с первого запуска без `--offline` после обновления; прежняя копия max
  в неё не переносится — и с ней расшифровки голосовых, услышанных до обновления. Кроме того:
  - голосовое — вложение `"kind": "voice"`, а не `"audio"` (в `inbox` и `review` пока `"audio"`);
  - `messages list --before` и `--after` разделились на `--before-id`, `--before-time`, `--after-id`,
    `--after-time`, а у `messages context` — `--before-n` и `--after-n`, как в tg. Скрипт со старым
    именем получит ошибку «неизвестный параметр»;
  - `messages list --before-id` не включает само это сообщение; с `--offline` годится только
    `--before-id`, и только с id сообщения из локальной копии;
  - `messages list --transcribe --json` больше не отвечает полем `transcribeProblem`: причина — в
    stderr; с `--offline` `unheard` пуст. Голосовое скачивается на отдельном соединении — с
    `--no-serve` это второй вход в MAX;
  - модели речи `max` ищет в `~/.cache/cli-common/models/audio`, одной папке с tg; скачанную в
    `~/.cache/max-cli/models/audio` нужно скачать заново или перенести;
  - `messages search` ищет слова и их начала (`квартир` найдёт «квартира»), а не любые три буквы
    подряд; `--chat` принимает и имя сохранённого чата.
- **`max chats list|show` и `max contacts list|show` — общие команды tg и max.** Их `--offline`
  отвечает из общей локальной копии, той же, что у tg.
  Почему: те же опции и ответы, что у tg.
  Что учесть: копия заполняется с первого запуска без `--offline` после обновления; прежняя копия max
  в неё не переносится, и до того `--offline` ответит `not_found`. Кроме того:
  - `chats list --search|--kind|--unread` без `--offline` ищет в 200 самых свежих чатах и пишет в
    stderr, если были старше; с `--offline` — во всех сохранённых;
  - `chats show --offline` отвечает без `description`, `access` и `settings`: их знает только MAX;
  - неверный `--kind` отвергается другими словами: `--kind is one of dialog, group, channel, saved`;
  - `cache clear` забывает и то, что этот аккаунт хранит в общей копии, а `contacts sync` забирает
    всё и туда.
- **`max messages send|edit|forward` — общие команды tg и max.** Ответы `--json`: `send` —
  `{sendId, operationId, message}` (с `scheduledFor`, если с `--at-time`), `forward` — тоже
  `{sendId, operationId, message}`, `edit` — `{operationId, message}`, вместо сообщения без обёртки. Так же отвечают инструменты MCP
  `max_messages_send`, `max_messages_edit` и `max_messages_forward`; у `max_messages_edit` больше нет
  `markdown`, у `max_messages_forward` — `send_id`.
  Почему: те же опции и ответы, что у tg, и номер действия, как в журнале отправок.
  Что учесть: скрипт, который читал сообщение из корня ответа, теперь берёт его из `message`. У
  `send` больше нельзя приложить несколько `--file` к одному сообщению: одно вложение из `--file` и
  одно из `--photo`. Если отправка с `--at-time` не получила ответа, ошибка советует
  `messages scheduled`, не называя чат.
- **`max polls` — общие команды tg и max.** `polls vote|close --json` отвечают `{operationId, poll}`,
  где `poll` — `{chatId, messageId, question, answers: [{id, text, voters, chosen}], closed, multiple,
  anonymous, voters}`; `polls create` — `{sendId, operationId, message}`. Так же отвечают инструменты
  MCP `max_polls_vote`, `max_polls_close`, `max_polls_create`.
  Почему: те же ответы, что у tg.
  Что учесть: у `max_polls_create` вместо `revote` теперь `silent`.
- **Ответы `--json` у реакций, закрепления и отметки прочитанным — общие с tg**, и в каждом есть
  `operationId`, номер этого действия, как в журнале отправок:
  - `reactions add|remove`: `{operationId, chatId, messageId, reaction}` — ваша реакция или `null`,
    без счётчиков реакций на сообщении (их показывает `messages list`);
  - `messages pin|unpin`: `{operationId, chatId, messageId, pinned}`, где `pinned` — `true` или `false`;
  - `chats mark-read`: `{operationId, chatId, until}` — до какого сообщения, или `null`, если до
    последнего.

  Так же отвечают инструменты MCP `max_reactions_add`, `max_reactions_remove`, `max_messages_pin`,
  `max_messages_unpin`, `max_chats_mark_read`.
- **`max messages unpin <чат> <сообщение>`** — теперь нужен номер сообщения, как у `pin` и в tg.
  В чате MAX закреплено одно сообщение, и открепляется оно, какой бы номер ни был указан. Инструмент
  MCP `max_messages_unpin` тоже просит `message`.
  Что учесть: `messages unpin <чат>` без номера получит ошибку — добавьте любой номер сообщения этого
  чата.
- **`max serve --detach` и `max serve --stop` убраны**: это `max server start` и `max server stop`.
  Почему: `serve` — только работа на переднем плане, а фоновым сервером управляет `max server`, как в tg.
  Что учесть: замените их в скриптах и службах, написанных вручную.
- **`max server status --json` отвечает теми же полями, что tg**: `byHand` стал `by` (`hand` — руками,
  `command` — его запустила команда, `server` — `max server start`, `unit` — служба); добавлены
  `log`, `unit` и `stale` (сервер упал и оставил метку). `max server start`, `stop` и `restart`
  отвечают как в tg: `{ started, by, pid, startedAt, log }` и `{ stopped, by, pid }`; поля `socket`
  больше нет.
- **`max messages send --at` теперь `--at-time`** — как во всех командах tg и max, где опция
  принимает время. Скрипт с `--at` получит ошибку «неизвестный параметр» — замените на `--at-time`.
  Параметр `at` у `max_messages_send` в MCP не меняется.
- **`--markdown` больше нет, только `--md`** — в `messages send`, `messages edit` и везде, где
  разметка читается. Так названо во всех командах tg и max; скрипт с `--markdown` получит ошибку
  «неизвестный параметр» — замените на `--md`.
- **`max sends list --json`: поле `cid` → `sendId`, и это строка, а не число** — то же имя, что в
  ошибке `outcome_unknown` и у `--send-id`. Строки, записанные раньше, показываются так же.
- **Записи запусков (`--trace`, `--record`, `max runs show`) — в общем формате tg и max.** Номер
  отправки в событии называется `send`, а не `cid`; ключ отказа MAX — `providerError`, а не
  `maxError`, в событиях, в `run.json` и в `details` ошибки `--json`.
- **`max bot` отвечает `outcome_unknown` (код `14`), если на отправку или другое изменение пришёл
  ответ 502, 503 или 504.** Раньше это был отказ `provider_unavailable` (код `12`).
  Почему: такой ответ даёт шлюз перед MAX, и он не говорит, выполнил ли MAX запрос. Сообщение могло
  уйти.
  Что учесть: скрипт, который повторял изменение после кода `12`, мог отправить его дважды. После
  кода `14` сначала проверьте, выполнилось ли оно. Чтение по-прежнему повторяется само и отвечает
  `provider_unavailable`.
- **Команды бота — под общими с tg именами, старых имён нет.** `max bot messages get <сообщение>` →
  `messages show <чат> <сообщение>`; `messages edit|delete` тоже берут чат первым; `bot chats get` →
  `chats show`; `bot chats pin|unpin` → `messages pin|unpin <чат> <сообщение>`. `--format markdown|html`
  → `--md` или `--html`; `--type` больше нет: картинку — `--photo`, голосовое — `--voice`, видео файлом
  — `--as-file`. `chats action` берёт `typing`, `photo`, `video`, `voice`, `file`. Отправка и правка
  отвечают `{ operationId, message }`, а не сообщением. Удаление спрашивает подтверждение,
  `--allow-dangerous` отвечает «да». Инструменты MCP бота переименованы так же: `max_bot_chats_show`,
  `max_bot_messages_show`, `max_bot_messages_pin`, `max_bot_messages_unpin`.
- **`max bot members` и `max bot admins` теперь `max bot chats members` и `max bot chats admins`**,
  как в tg. `admins add` берёт `--can` со словами `max chats admins add` (`read`, `members`, `admins`,
  `info`, `pin`, `link`, `edit`, `delete`) вместо `--permissions`, и `--title` вместо `--alias`.
  Прав «звонки» и «статистика» в `--can` нет. `admins list` отвечает `{ id, name, username, role,
  rights, title }`. Инструменты MCP: `max_bot_chats_members_list|add|remove`, `max_bot_chats_admins_list`.
- **Команды, которые меняют только этот компьютер, теперь отмечены как записи.** `config set` и
  `unset`, `chats rules set` и `unset`, `recipients add`, `remove` и `clear`, а у бота `auth set` и
  `remove`, `chats rules set` и `unset`, `recipients add`, `remove` и `clear` пишут файл настроек,
  файл правил групп, списки получателей или связку ключей — и ничего в MAX. В
  [списке команд](docs/commands.md) у них строка «Меняет что-то только на этом компьютере.», а
  `max commands` показывает их в колонке `writes`. Раньше они не были отмечены вовсе.
  Что учесть: агент или скрипт, который по `max commands --json` отбирает только чтение, теперь
  не увидит их среди безопасных команд.

### Исправлено

- **`max store fetch` по времени больше не пропускает сообщение на границе страницы** и
  останавливается, если MAX раз за разом отдаёт одну и ту же страницу.
- **`max messages list --before-time` не показывает сообщение, отправленное ровно в эту миллисекунду**:
  «до» значит «раньше».
- **`max messages list --after-id` (в 0.21.0 — `--after <id>`) говорит, что есть следующая страница,
  когда она есть.** Раньше при чтении вперёд от сообщения команда всегда отвечала, что дальше ничего нет.
- **`max messages send --voice` теперь уходит и через `max serve`.** Раньше через сервер MAX
  отказывал (`proto.payload`, код `11`): полоска громкости голосового терялась по дороге. Без
  сервера (`--no-serve`) голосовое уходило и раньше.
- **`max chats list` и `max chats show` больше не показывают чаты, из которых вы вышли.** Раньше
  такой чат оставался в списке навсегда, с устаревшим числом участников. Теперь он исчезает при
  следующем входе, если max получил от MAX полный список ваших чатов; сообщения остаются в копии до
  `max cache clear --left`. `max serve` узнаёт о выходе только при следующем полном входе.
- **`max serve` больше не путает ответы после долгой работы.** Номер запроса занимает два байта и
  после 65 536 запросов начинается заново. Если запрос с тем же номером ещё ждал ответа, новый
  запрос мог получить чужой ответ. Теперь такой номер пропускается.

  делает то, что они разрешают: сообщает, удаляет сообщение, удаляет человека из группы.
  Что учесть: по умолчанию команда только сообщает; `--dry-run` только планирует; за раз — не больше
  10 действий. Удаление и исключение проходят те же проверки, что любое другое изменение. Заявки на
  вступление в этой версии только планировались — в 0.17.0 их убрали совсем, потому что в MAX их нет.
  Подробнее — [docs/groups.md](docs/groups.md).

  `max_chats_members`, `max_chats_rules`.
  Что учесть: без флага инструмента проверки нет. Действия, которые правила велят подтвердить, агент
  показывает вам одной формой.
- **Роли и ссылка.** `max chats members list` помечает каждого участника `owner`, `admin` или
  `member`. `max chats link show <чат>` печатает ссылку-приглашение.

  видео, которое смотрят прямо в чате (`.mp4 .mov .webm .mkv`). `max messages send <чат> --voice
  заметка.ogg` отправляет голосовое с полоской громкости и длительностью.

  Подробнее — [docs/usage.md](docs/usage.md).
- **Голосовые текстом прямо в списке.** `max messages list <чат> --transcribe` и `max inbox
  --transcribe` расшифровывают показанные голосовые на этом компьютере; текст стоит под сообщением

  скачанная модель.

  шлёт события на оба.
- **Локальная копия переписки бота.** Всё, что бот прочитал, отправил или получил, сохраняется на
  этом компьютере. `max <имя> bot messages list <чат> --offline` и `messages get --offline` читают её

  Что учесть: сообщение, удалённое ботом или удаление которого заметил `updates watch`, из копии
  пропадает. Копия содержит тексты сообщений.
- **`max <имя> bot updates watch`** печатает события бота по мере прихода, до Ctrl-C, и сохраняет их

### Безопасность

- **Токен из `MAX_TOKEN` остаётся только там.** Если MAX выдаёт сессии новый токен, `max` не пишет
  его ни в ключницу, ни в файл, а говорит об этом в stderr. `max doctor` называет файл
  `credentials.json`, если токен хранится в нём, а не в ключнице.
- **`max session start` показывает номер телефона скрытым**, как `max account show`. Ctrl-C на
  вопросе о токене завершает команду с кодом `130`.
- **Фоновый сервер не отдаёт токен** командам, которые спрашивают у него вход: им он не нужен, они
  сверяются с ключницей.
- **Пределы для сети.** Кадр MAX распаковывается не больше чем в 32 МиБ. Подключение к MAX и
  скачивание файла не висят бесконечно, если сеть замолчала. `max messages download` скачивает только
  по https, не ходит по ссылкам на этот компьютер и в локальную сеть — в том числе после
  перенаправления — и не качает больше 4 ГиБ; голосовое для расшифровки — не больше 32 МиБ.
  Почему: ссылка в сообщении приходит от чужого человека и может вести куда угодно.
- **Права на локальную копию.** База и её журналы `-wal` и `-shm` создаются с правами `0600`,
  каталог — `0700`; права старых файлов выставляются так же при следующем открытии. В отчёте о
  проблеме номера чатов и сообщений заменены метками.
- **Чужой текст печатается в одну строку, а управляющие символы — видимыми** — в ленте, таблицах,
  списке кандидатов, выгрузке Markdown и путях `messages download`. Из имени скачанного файла
  убираются управляющие символы и символы смены направления текста. В Markdown ссылками становятся
  только адреса `http` и `https`.
- **Автодополнение на месте чата или человека подставляет только номер**, а название или имя
  показывает рядом. Почему: название и `@имя` задаёт кто-то другой, и оболочка не должна получать от
  него ничего, кроме цифр.
- **`max cache clear` без имени профиля очищает профиль по умолчанию и учитывает `MAX_PROFILE`.**
- **Выпуск строже.** Версии зависимостей закреплены точно; пакет собирается с нуля перед каждой
  упаковкой, без тестовых помощников; публикует отдельный шаг, который не ставит и не запускает
  зависимости.

  веб-версия не шлёт, и просил 40 чатов за раз.
  Почему: чем меньше `max` отличается от веб-клиента, тем меньше у MAX поводов его заметить.
  Что учесть: список чатов тот же. Проверено на канале с непрочитанными: чтение по-прежнему ничего не
  отмечает прочитанным.
- **Описание устройства берётся с вашего компьютера:** часовой пояс, язык системы и операционная

  и тем же Chrome на Linux в часовом поясе Мадрида.

  контактах, и в групповом чате почти все были номерами. Имена берутся одним запросом и сохраняются,
  так что следующее чтение их уже не спрашивает. То же — для авторов ответов и пересылок.
- **Выпуск версии больше не останавливается сразу после публикации, не поставив тег.** Так было
  дважды; теперь версия проверяется в обход кэша npm, с ожиданием до трёх минут.

## 0.3.0 — 22.09.2026

### Что нового

- **Переписка читается лентой:** разделитель при смене дня, строка `время  автор` и текст под ней,
  выровненный по колонке, с переносами по ширине терминала. `вы` — ваши сообщения; автор без имени
  показан номером. `↳` — на что ответ, `↪` — чья пересылка: MAX присылает их целиком, и они
  сохраняются в локальной копии.
- **`-v` и `-vv` — подробнее:** id сообщения, отправителя, чата и адреса вложений; затем всё, что
  известно о сообщении.
- **`--jsonl` — по объекту JSON на строку**, для потока и `jq`.
- **Вложения показываются ссылками:** `📎 photo`, `📎 photo ×3 1 2 3`, `📎 файл.pdf · 24 MB`. В JSON —
  `url`, `width`, `height`, `title`.
  Что учесть: ссылка на фото открывается без входа — кому её переслали, тот и увидит фото.
- **`senderColors: true` в настройках профиля — свой цвет у каждого автора.** По умолчанию выключено.

### Изменено — может сломать скрипты

- **`-v` теперь означает подробность вывода, а версия — `max -V`.** Строки о запросах на stderr
  включает **`--trace`** — это бывший `--verbose`.
  Что учесть: скрипт, который звал `max -v` за версией или `--verbose` за трассировкой, должен
  перейти на `-V` и `--trace`.
- **Флаг `--query` у списков переименован в `--search`** (в описании этой версии изначально не был
  указан).
- **Локальная копия переходит на схему 4 и при первом запуске собирается заново.**
  Что учесть: прочитанная история в этой версии не сохраняется — её придётся прочитать снова.

### Исправлено

- **Имя, подходящее к нескольким чатам, выводит их списком с id**, а в JSON — полем `candidates`.
- **Предупреждение о локальной копии называет схему и что делать.** Раньше причина называлась словом
  `Error`.
- **Подсказка о следующей странице у `messages list` советует `--before <id>`.** Раньше она советовала
  несуществующий `--page`.

## 0.2.0 — 22.09.2026

### Что нового

- **`max messages send --silent` — отправить без уведомления у получателя.**
  Что учесть: что именно MAX делает с этим флагом, пока не наблюдали — для этого пришлось бы написать

- **Токен обменивается при первом входе.** MAX отвечает на вход своим токеном, и `max` сохраняет его в

- **Профиль привязан к своему аккаунту.** Токен чужого аккаунта в профиле — отказ с объяснением.
  Почему: иначе команды профиля пошли бы от чужого имени.
- **Подсказка после неясного исхода отправки называет существующую команду.** Раньше она называла

## 0.1.0 — 21.09.2026

Первая версия, которой можно поделиться.

### Что нового

- **Семь команд против настоящего MAX:** `session start|end`, `account show`, `chats list`,
  `contacts list`, `messages list`, `messages send`.
- **Профиль — первое слово:** `max personal chats list`. Несколько аккаунтов живут рядом, у каждого
  свой токен, своё состояние и своя локальная копия. То же задаёт `MAX_PROFILE`.
- **Токен хранится в ключнице операционной системы**, а не в файле и не в аргументе команды.
  Что учесть: своего входа по номеру телефона пока нет — `max session start` берёт токен из
  официального клиента.
- **Машинный режим:** `--json` кладёт на stdout ровно одно значение JSON и ничего больше; то же
  включается само, когда stdout не терминал. Ошибка уходит на stderr, stdout остаётся пустым.
  Ветвиться можно по коду выхода — таблица в [`docs/commands.md`](docs/commands.md).
- **Диагностика без содержимого:** `--verbose` показывает по строке на запрос, `--record` кладёт их в
  каталог запуска на 30 дней, `max runs list|show|path` читает обратно. По умолчанию не записывается
  ничего.
- **Локальная копия:** прочитанное сохраняется рядом; `--offline` отвечает из неё, не подключаясь, а
  `max cache clear` её забывает.
- **Настройки в `~/.config/max-cli/config.json`**, с порядком «флаг → переменная окружения → файл →
  встроенное значение». Опечатка в имени поля — ошибка с именем поля, а не молчаливое умолчание.
- **Два рантайма:** Node 22+ и Bun 1.3+; собранная команда выполняется под обоими в CI.
- **Чтение ничего не помечает прочитанным.** «Получить историю» и «отметить прочитанным» — разные
  операции протокола; вторая не отправляется никогда, и это проверяется тестом.
- **Отправка не врёт об исходе.** Если ответ не пришёл — `outcome_unknown` (код `14`), а не «ошибка» и
  не «отправлено».
  Что учесть: повторять такую отправку можно только с тем же `--cid`, иначе сообщение может уйти
  дважды.
- **Протокол MAX неофициальный и разобран обратной инженерией:** это не Bot API.
  Что учесть: он может измениться без предупреждения; тогда команда скажет об этом одной строкой в
  stderr, а не сломается молча.
- **Пока не умеет:** входить по номеру телефона, работать с вложениями, реакциями, правками, группами,
  историями и звонками — только текст. Массовой рассылки не будет: это инструмент для личного
  аккаунта.
